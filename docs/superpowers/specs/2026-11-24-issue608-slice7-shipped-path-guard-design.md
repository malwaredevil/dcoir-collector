## 1. Problem and source evidence

The existing duplicate-function action implements both Resolve-CollectorReportPath and ConvertTo-MarkdownTableCell inline in .github/actions/run-duplicate-function-check/Invoke-DcoirDuplicateFunctionCheck.ps1 (blob 6ba6bcc1b8f028399fa91d53f24901a7d20ae905). The Python contract suite .github/github_actions/tools/test_duplicate_function_action_contract.py (blob aa7f52b45ab63411db13a659eb7c973e95f73c71) independently implements normalize_report_path and markdown_table_cell. Its behavioral assertions therefore prove the mirror rather than the shipped functions; substring checks alone do not establish that the live implementation rejects hostile input or preserves escaped output. Remove that competing test implementation, not the independent report validator.

The full Windows jobs in .github/workflows/reusable-validate-on-pr.yml (blob 0693e1df668df08883d1f6f111baeec2edf9da3a) and reusable-validate-on-push.yml (blob 93b7fcf6186190caf359179069341cfabd9b06c5) already run the Python contract test before calling the duplicate-function composite action, via pwsh shell and an explicit nonzero Python exit gate. The Ubuntu Draft fail-fast script also invokes that Python module. The current action dispatches its repository-local entrypoint via DCOIR_ACTION_SCRIPT and pwsh. The Windows PowerShell 5.1 validation separately parses tracked PowerShell files. Reuse these lanes without editing workflow YAML.

## 2. Scope and ownership

Create .github/actions/run-duplicate-function-check/DuplicateFunctionCheck.Paths.ps1 as a definitions-only script containing the two existing function bodies. The shipped entrypoint must dot-source this exact sibling using its own script directory (PSScriptRoot), before either function is called. Remove the inline definitions from the entrypoint. Keep existing repository-root initialization and its location contract; the helper must use the same root state when called by the production entrypoint. Tests establish the same contract in a scratch repository and must not use a duplicate path algorithm. Do not move Get-RepoRelativePath or duplicate-function scanning, change report schemas, alter defaults or action inputs, change the static-analysis gate, merge scanners, or introduce a generic framework. Preserve the two function names and parameter interfaces, actual returned FullPath and RelativePath, normalization/case rules, error conditions, Markdown escaping order, and caller behavior.

Add .github/scripts/Test-DuplicateFunctionCheckPaths.ps1 as a native table-driven executable self-test. It loads the exact production helper from the checkout using a script-relative absolute path, never a copied body, AST-generated replacement, or Python port. Execute tests from an isolated disposable filesystem directory with a synthetic project_sources/collector subtree, initialize repository-root state exactly as in production, and restore location and remove only owned fixtures in finally. Dot-sourcing the helper itself must not run the action, emit reports, alter location, or exit the process. Tests must not invoke a live collector or access unrelated files.

Revise the existing Python contract suite to remove normalize_report_path, markdown_table_cell, and mirror behavioral tests. Keep structural checks for action defaults, entrypoint dispatch, exact production-helper loading before first call, one owner of both definitions, report-schema markers, shared discovery and workflow ordering. Structural checks are supplemental and not evidence of behavioral safety. On Windows, invoke native pwsh as a child with NoProfile, NonInteractive and a fixed repository-owned script path; use argument-list subprocess execution, no shell interpolation, bounded timeout, and nonzero/missing execution evidence failure. Missing executable, missing helper, missing test script, zero cases, wrong completion marker, timeout or nonzero exit must fail the Windows Python contract test. Report actual positive/negative case counts and native success; the completion marker alone is not a substitute for executed assertions. Do not allow an environment variable to silently disable the native suite on Windows. For Ubuntu Draft fail-fast keep structural checks runnable without PowerShell, explicitly skip the Windows-native behavioral test and distinguish that skip from a pass. No new dependencies or YAML edits. Optional local non-Windows PowerShell runs may supplement, not replace, Windows evidence.

Retain .github/github_actions/tools/lib/duplicate_function_report_contract.py unchanged as independent post-hoc JSON/Markdown validation; it has its own artifact validation responsibilities and stricter output filename/physical containment requirements. It is not the removed test mirror.

Update the action README to describe the shared owner and how to run the native suite through the existing Python driver. Refresh generated PowerShell surface inventory, analyzer baseline/shards, reachability and other affected generated evidence through their canonical generators only when readback demonstrates the source change requires it. Check all changed/new governed files against the 15,000-byte source limit. Do not relax analyzer policy, suppress new findings, or rewrite unrelated generated data to manufacture a pass. The new PowerShell scripts must be correctly inventoried as maintained support scripts and be compatible with the Windows PowerShell 5.1 parser. Neither action.yml nor workflow YAML is intended to change.

## 3. Behavioral acceptance and test strategy

Use test-first development: demonstrate the missing helper/direct-execution contract fails on the baseline; extract the functions, then demonstrate the native suite passes. Capture the actual baseline semantics before changes (using the immutable original source in a disposable isolated comparison if needed), not another handwritten implementation.

Reproduce every existing mirror input and expected outcome against the production helper: accepted canonical JSON path, backslash-normalized Markdown path, blank input, rooted POSIX path, rooted Windows drive path, parent traversal, wrong subtree, wrong extension, embedded newline, DEL control character. Add whitespace-only/null values, leading/trailing ordinary whitespace, mixed separators, uppercase allowed suffix, distinct JSON/Markdown paths, leading/trailing controls before trimming, tab/NUL/CRLF, UNC/device-like and drive-relative inputs, collector prefix lookalikes, case-sensitive subtree spelling, safe nested paths and legitimate names containing two dots without a traversal segment. Assert both normalized relative value and exact absolute path for valid cases, and appropriate rejection for hostile cases. Reject test false positives: a catch block must not accidentally swallow the test's own assertion failure, and an unrelated exception is not proof that the intended guard rejected a case. Run safe controls alongside hostile ones; no case may touch outside the disposable fixture.

Markdown cases cover null/empty, plain text, LF/CRLF, ampersands, angle brackets, pipes, backticks, existing entity-like text, combined characters and numeric conversion. Assert exact escaped results (including order and line-ending behavior); no loss of expected escaping or additional output. Do not change existing semantics solely to make a novel test pass. Validate actual action wiring, including loading the helper and keeping output checks before write, and unchanged action output on representative safe inputs. Obtain clean and seeded duplicate/parse-failure report parity evidence against the immutable pre-slice production entrypoint with the same fixture inputs and PowerShell version. Compare JSON and Markdown bytes where deterministic; if a field depends on fixture location/runtime, explain and control that dependency before claiming parity. Keep central gate behavior and independent report validator success/failure semantics unchanged.

Security boundary: the current guard uses lexical GetFullPath and a repository prefix comparison; that is not proof of physical containment through NTFS junctions, reparse points, symlinks or path aliases. Include disposable Windows fixture probes for junctions and alias forms, with no attempted report write outside the scratch fixture. Distinguish observed legacy behavior from required security expectations. If these probes confirm a preexisting containment defect or identify a behavior change necessary for safety, stop and present exact evidence and a bounded hardening proposal for separate approval; do not silently widen the agreed extraction, accept an unsafe result as a security pass, or weaken tests. No claim of physical containment until demonstrated. Keep all probes local to fixtures; no operational network or user data.

Demonstrate test sensitivity in an isolated scratch copy (not the governed production branch): temporarily remove/disable a guard condition or an escaping operation and verify that the direct suite fails, then restore and verify green. Also prove missing helper, missing native executable on Windows, nonzero child result and missing/zero-case completion evidence fail the driver. Ensure Linux Draft static contract cannot be mistaken for Windows behavior evidence. No mutable fixture-generated source should become the production implementation.
